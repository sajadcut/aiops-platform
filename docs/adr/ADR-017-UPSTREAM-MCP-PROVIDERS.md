# ADR-017 — Upstream MCP Provider Contracts

**Status:** ACCEPTED

## Decision

For primary observability integrations, the Control Plane SHALL target the actual upstream MCP contracts rather than project-invented tool names:

- Prometheus: `prometheus/prometheus-mcp`.
- Zabbix: `initMAX/zabbix-mcp-server`.
- Elastic: **Elastic Agent Builder MCP served by Kibana**.

The deprecated standalone `elastic/mcp-server-elasticsearch` provider is no longer a supported AIOps production or compatibility target.

The AIOps domain contracts (`get_metrics`, `get_alerts`, `get_logs`) remain internal and stable. Provider adapters translate those operations into the selected upstream MCP tool contracts.

## Provider mappings

### Prometheus

Canonical metric evidence -> upstream `range_query` with deterministic PromQL generated by the adapter. Alert evidence -> upstream `list_alerts`.

Destructive/admin capabilities are not part of the Control-Plane allowlist.

### Zabbix

Canonical active-alert evidence -> upstream `problem_get` with bounded time/search/limit arguments. Optional multi-server routing uses `ZABBIX_MCP_SERVER_NAME`.

Only explicitly selected read-only monitoring tools are allowlisted. Broad/raw or write extensions remain forbidden in the Evidence path.

### Elastic Agent Builder MCP

Minimum supported Elastic Stack is **9.2** because the Kibana Agent Builder MCP endpoint was added in 9.2. The recommended Production baseline is **9.3 or newer**; production promotion should use a specific patched release approved by the organization.

Canonical endpoint:

- default space: `{KIBANA_URL}/api/agent_builder/mcp`
- custom space: `{KIBANA_URL}/s/{SPACE}/api/agent_builder/mcp`

The adapter scopes discovery with the MCP `namespace` query parameter and requires `platform.core`.

Canonical log Evidence -> `platform.core.execute_esql`. The adapter constructs bounded deterministic ES|QL from trusted service/time/level fields and a configured `ELASTIC_AGENT_BUILDER_INDEX_PATTERN`. Agents never supply arbitrary ES|QL, Query DSL, tool names or index patterns.

`platform.core.search` and `platform.core.generate_esql` are intentionally not used by the EvidenceCollector because they introduce an additional AI/query-generation layer inside evidence acquisition. They may be evaluated later only through a separate governed ADR and acceptance process.

The configured API key must be least-privilege. For the selected read-only query path, index `read` is required; any additional Agent Builder or Kibana privileges must be limited to those required for the MCP route/tool set. Agent Builder tool execution must not replace AIOps Policy/Approval/Verification authority.

## MCP transport requirements

The shared MCP client implements Streamable HTTP lifecycle and response handling: `initialize`, `notifications/initialized`, negotiated protocol version, optional `Mcp-Session-Id`, JSON responses and SSE event responses.

Protocol negotiation remains provider-driven. AIOps does not fabricate non-standard HTTP routing headers as part of the upstream contract.

## Authentication

Each provider may use a distinct full `Authorization` value:

- `ZABBIX_MCP_AUTH_HEADER`
- `ELASTICSEARCH_MCP_AUTH_HEADER`
- `PROMETHEUS_MCP_AUTH_HEADER`

For Elastic unattended Control-Plane use, API key authentication is the default target. OAuth 2.1 may be used only where the deployment type and enterprise identity architecture support it. The generic `MCP_BEARER_TOKEN` remains a fallback for providers that use Bearer authentication. Write identities remain separate from read identities.

## Security constraints

Agents never receive a raw MCP client and never choose arbitrary remote tool names. They also never supply arbitrary PromQL, ES|QL/Elasticsearch Query DSL or Zabbix raw API calls. EvidenceCollector/provider adapters own deterministic query construction. Mutation capabilities remain behind Decision -> Policy -> Approval -> Execution and require a separate execution identity.

## Deployment acceptance

Production acceptance requires deployment of the selected upstream MCP services in the restricted network, TLS/authentication validation, tool-list/schema verification against pinned provider versions, least-privilege credentials and real endpoint tests. For Elastic this specifically requires Kibana/Elasticsearch Agent Builder >= 9.2, with >=9.3 recommended, the correct Space-aware MCP URL, required feature/license availability, and validation of the allowlisted `platform.core.execute_esql` tool.
