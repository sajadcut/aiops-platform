# قانون الزام‌آور گزارش هوشمند مبتنی بر آلارم

این قانون برای **تمام** رخدادهای AIOps و تمام فناوری‌ها برقرار است؛ نه فقط Redis و nginx.

## قرارداد

1. منبع اصلی سؤال اپراتور، **متن سیگنال دریافتی و ذخیره‌شده همان Incident** است، نه تشخیص عمومی سیستم‌عامل. متن حساس باید Redact شود. اگر متن اولیه قابل بازیابی نیست، فقط خلاصه Incident استفاده شود و این تفاوت آشکار باشد.
2. آغاز بخش «گزارش هوشمندِ مبتنی بر شواهد» باید به همان آلارم پاسخ دهد: منبع و متن هشدار، بررسی‌های مرتبط و واقعی، وضعیت تأیید ادعا، محدودیت شواهد، فرضیه‌های جداشده و بررسی بعدی.
3. هر تست مرتبط باید با Evidence ID، Tool و نتیجه ثبت‌شده عرضه شود. تستی که اجرا نشده، نباید اجراشده، موفق یا ناموفق معرفی شود.
4. هویت سرویس را مستقل بررسی کنید؛ تست سرویس دیگری روی همان میزبان نباید شاهد این آلارم تلقی شود. شواهد عمومی systemd فقط برای آلارم سلامت سرویس مستقیماً مرتبط هستند و برای آلارم Redis/DB/MQ/HTTP شاهد مکمل‌اند.
5. پاسخ TCP یا HTTP موفق به معنی سلامت احراز هویت، TLS، Connection Pool یا تراکنش برنامه نیست. متن خود هشدار نیز به معنی اثبات علت ریشه‌ای نیست.
6. نتیجه Agent و Cognia فقط فرضیه/تجربه هستند تا وقتی Evidence تازه و مرتبط آن‌ها را تأیید کند. LLM در تولید متن به این قانون ملزم است؛ خروجی Deterministic حتی هنگام خاموشی یا خطای LLM باید وجود داشته باشد.
7. رفع خطای کانفیگ، Proposal، Approval، اجرای MCP و Verification مجزا هستند. گزارش خواندنی هیچ اختیار اجرایی صادر نمی‌کند.

## معیار پذیرش

- **آلارم Redis + systemd active:** گزارش با متن آلارم Redis شروع می‌شود؛ systemd در بخش مکمل است. اگر تنها TCP تست شده، سلامت واقعی Redis/کلاینت «تأیید نشده» است.
- **آلارم دیتابیس + Redis سالم:** تست Redis نباید تست دیتابیس محسوب شود.
- **آلارم HTTP 503:** فقط نتایج HTTP همان وابستگی و آدرس تأییدشده به‌عنوان بررسی مرتبط نمایش داده شوند.
- **آلارم ActiveMQ + Recovery بعدی:** پیام اصلی PROBLEM برای تحلیل حادثه حفظ می‌شود؛ Recovery جداگانه یک ادعای جدید است.
- **فناوری ناشناخته:** تطبیق بر مبنای واژه تخصصی واقعاً مشترک میان آلارم و نتیجه ابزار انجام شود؛ در نبود تست مستقیم، صریحاً «بررسی مرتبط ثبت نشده» گفته شود.
- **شناسه سرویس متفاوت:** ردیف MCP برای سرویس دیگر نمی‌تواند پاسخ آلارم باشد.
- **بدون LLM یا بدون Evidence:** بخش آلارم همچنان نمایش داده می‌شود؛ هرگز Healthy یا Root Cause Confirmed جعل نمی‌شود.
